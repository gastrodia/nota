# Part A 与 Part B 的实现边界

Part A 描述完整产品的设计；Part B 保留 Next.js / Node.js / PostgreSQL 的最小可用实现。此文说明代码实际保证，不修改 Part A 原答卷。

## 业务幂等和额度（T6）

一次额度对应一个逻辑 AI 任务，包含该任务的模型决策、工具调用与最终整理；单独 ASR 不扣整理次数，但有启动频率与剩余额度检查。按北京时间每日 10 次，`usage_daily.used` 包含预占和已消耗数量。

同一用户、同一便签只对应一个原始整理任务。换浏览器请求键、并发提交、失败后重试均复用原任务；所有请求键及输入绑定保存在 `job_requests`。原文变化返回冲突，用户应创建新便签，不能借重试覆盖已执行行动。用户有意新建的另一条便签不会只因文字相同被合并。

没有已提交行动的失败退还预占；已经创建待办后其他阶段失败保留一次扣费，恢复时复用工具执行账本。任务及其重试归原提交日，跨日不重复扣次。

迁移保留旧版本已有重复任务和副作用，不能将新增唯一约束误认为历史数据已自动修复。

## Agent 追问与行动（T3）

Agent 可以创建待办、检索历史以及发起澄清。明确要求无截止日期的待办可以保存；时间含糊或证据冲突时，先询问用户。待确认行动和上下文快照持久化，后续补充与授权校验使用同一段有界会话上下文；原任务重试不会获得更新对话中尚未属于该任务的授权。

语音/文字便签与 Agent 使用相同会话标识，追问在可继续答复的位置展示。待办只代表列表内的行动记录，目前没有日历写入和主动推送提醒，不承诺到时通知。

## 录音原件与恢复（T7、T9）

实际编码的原音按账户保存在 IndexedDB，保留稳定采集 ID、录音时间和确认文字。转写失败或刷新后可以恢复原音，再将原音解码为 PCM 重试转写。无文字时也可以先保存云端原音。云端草稿可以重新加载原音继续转写；服务端仍使用私有存储和账户鉴权。

浏览器存储不是设备级永久存储：用户主动清除站点数据、浏览器回收空间或无法使用 IndexedDB 时不能保证保留，界面应提示下载原音。现有本地缓冲不等于网页能无限制后台录音或离线运行云端模型。

## 后台处理（T7）

提交事务保存任务后，通过 Next.js `after` 在返回响应后启动执行，减少对页面持续打开的依赖。另有独立 `pnpm worker` 或受密钥保护的调度接口兜底扫描 PostgreSQL 队列。

调度器处理 pending、租约过期的 running，以及明确可重试的 failed 任务。重试间隔从 15 秒指数递增，最多 300 秒、最多五次执行。模型权限/参数拒绝和配置错误不会自动重试。租约耗尽的终态任务结算额度，避免预占永久悬挂。工具执行使用 fence 和账本防止旧执行器重复写入。

生产必须实际运行持久 Worker 或配置周期调度；仅部署 API 不代表独立调度已启用。详见 README 的后台执行说明。

## 历史检索（T4）

`recorded_at` 代表实际录音/记录发生时间，`created_at` 是云端创建时间。补传录音保留原录音时间；旧资料回填原创建时间，不猜测真实历史日期。

检索采用账户与时间过滤、有限同义词扩展和原文证据；客户名、编号等实体条件不会因为同义词扩展被丢掉。多份报价存在不同金额时先澄清，而不默认最新就是正确答案。长原文选择包含较多查询条件的片段，并标明截断。

没有实现 pgvector、通用语义搜索、用户偏好记忆或自动业务事件时间抽取。有限词典只能改善已覆盖表达，不能宣称解决所有同义问法；增加向量检索前应先扩充召回评估。

## 效果评估（T5）

固定样本覆盖关键事实保留、受约束的虚构检测、实际待办精确率/召回率、时间、来源支持、历史缺失、追问、冲突和检索材料注入。报告记录数据集及提示词/代码指纹、模型配置、合成模型原始请求与回答和耗时，可对比前后报告。

自动断言只对已定义的事实和样本有效，仍需人工复核开放摘要，不将全通过表述为通用准确率。真实模型评估只写独立本地测试库的合成账户，执行后删除该轮合成账户。
